====================================================================
 ASHIGARU DESKTOP - TESTING CHECKLIST
 Release: 1.4.5  (branch v1.4.5)
====================================================================

HOW TO USE
  - Build and run locally:  ./gradlew run
  - Most items need Tor + a live Electrum/Dojo connection on MAINNET.
  - The passphrase-warning and discovery tests need a real wallet
    that already has on-chain history.
  - This is a MANUAL checklist - no automated tests were added.
  - Mark each item [x] pass / [!] fail (add a note).


--------------------------------------------------------------------
 0. BUILD & LAUNCH
--------------------------------------------------------------------
  [ ] ./gradlew run builds cleanly (no compile errors).
  [ ] App launches at ~1100x800.
  [ ] Window will NOT resize smaller than 800 x 760.
  [ ] Splash / logo renders crisp; macOS shows the dock icon.
  [ ] Status bar shows MAINNET | Block height | Connected once
      Tor / Electrum connect.


--------------------------------------------------------------------
 1. WALLET CREATION & RESTORE
--------------------------------------------------------------------
  [ ] "+ New / Restore" flow is dark-themed, step-by-step, cohesive.
  [ ] Seed-word entry grid is numbered and theme-compliant.
  [ ] Restore accepts a valid 12/24-word seed.
  [ ] Create a wallet WITH a BIP39 passphrase.
  [ ] Create a wallet WITHOUT a passphrase.
  [ ] (Optional) Create an encrypted wallet (with a password) to
      exercise that path separately.


--------------------------------------------------------------------
 2. BIP39 PASSPHRASE HANDLING  (primary focus)
--------------------------------------------------------------------
  [ ] Open a passphrase wallet (with existing history) using the
      CORRECT passphrase -> loads normally, NO warning, correct
      UTXOs/history.
  [ ] Open the same wallet with a WRONG passphrase -> a different/
      empty wallet loads, then on the first full history refresh the
      "Reopen <name>?" warning appears.
        [ ] Reopen Wallet -> wallet unloads, passphrase prompt
            reappears; correct passphrase then loads real history.
        [ ] Refresh Wallet -> proceeds with clear/rescan (no reopen).
  [ ] Cancel the passphrase prompt when opening -> wallet not opened,
      clean "passphrase required" message, no crash.
  [ ] Lock button shows for passphrase wallets AND encrypted wallets.
  [ ] Click Lock -> wallet returns to locked state in the selector;
      re-selecting prompts for the passphrase again.
  [ ] Delete an unencrypted passphrase wallet: correct passphrase
      deletes; wrong passphrase is rejected ("Incorrect Passphrase -
      not deleted").
  [ ] Delete an encrypted wallet requires the correct password.


--------------------------------------------------------------------
 3. WHIRLPOOL / MIXING RACE
--------------------------------------------------------------------
  [ ] Open a passphrase wallet WHILE Tor is still connecting ->
      no NullPointerException; wallet opens; Whirlpool starts once
      connected.
  [ ] Mixing starts normally for an open wallet after connection.
  [ ] With the coordinator unreachable, a clear "coordinator
      unreachable" warning is shown (not a silent failure).

 12. WHIRLPOOL ENGINE CLEANUP ON DELETE / MIX BUTTON RECOVERY
--------------------------------------------------------------------
  [ ] Start Postmix mixing on a wallet, then Delete that wallet ->
      no error, wallet disappears from the sidebar as normal.
      (Can't observe the background engine directly from the UI -
      this is really confirming the delete path doesn't hang or
      throw; the engine teardown itself is covered by an automated
      test, see WhirlpoolServicesTest.)
  [ ] Configure wallet B's Mix To -> wallet A, then Delete wallet A ->
      re-open wallet B's Mix To dialog: it should show "Mix To..."
      (cleared), not still pointing at the deleted wallet.
  [ ] Lock (not delete) a wallet that is actively mixing -> mixing
      keeps running in the background as before (this is intentional,
      NOT a regression - only Delete should stop it).
  [ ] Click "Start Mixing" on a Premix/Postmix account with nothing
      currently eligible to mix (e.g. right after a fresh Tx0, before
      confirmations) -> button should NOT get stuck on "Starting...";
      it should settle back to a normal Start/Stop state once the
      engine actually starts.
  [ ] Switch between wallets (or between Deposit/Premix/Postmix/
      Badbank tabs) repeatedly while one wallet has mixing running ->
      the Start/Stop Mixing button always reflects the correct state
      for whichever account is currently active, never stuck from a
      previously-viewed account.
  [ ] Disconnect Tor/network, then click "Start Mixing" so the start
      attempt fails -> button recovers to a clickable state instead
      of staying on "Starting..." forever.

  [ ] The package matching this install is preselected; the others are

  [ ] The headless "ashigaru-server" build is never preselected, but

 18. CLEARNET TLS                                         (new in 1.4.1)
--------------------------------------------------------------------
  CRITICAL - must be run against a PACKAGED build, never ./gradlew run.
  A development run uses the full JDK, always has SunEC, and therefore
  cannot reproduce the fault or demonstrate the fix. Published 1.3.0
  fails every check below.

  [ ] Settings -> Update -> "Check now" reaches GitHub and reports a
      version, rather than "Received fatal alert: handshake_failure".
      This confirms jdk.crypto.ec made it into the jlink runtime image.
  [ ] ashigaru.log carries no handshake_failure line for the startup
      update check.
  [ ] Tools -> Whirlpool Stats loads with NO proxy configured, which
      exercises its clearnet HTTPS path rather than the onion mirror.

 22. NIKKYOU SANS ON CHROME                               (new in 1.4.5)
--------------------------------------------------------------------
  NOTE: Nikkyou Sans is now the application default (.root). Data
        that must stay monospaced pins the family back explicitly.
        So the question is no longer "did this screen get the font"
        but "did anything lose its monospace that needed it".

        Bold is gone from everything except the four monospaced value
        classes: no bold face is bundled for either family, so it was
        always synthesised or falling back to a system face.

  [ ] Sidebar: wordmark, "CURRENT WALLET", Open Wallet, + New /
      Restore, Tools, Settings all in Nikkyou Sans.
  [ ] Settings and Tools: page titles, nav buttons, back button and
      every action button.
  [ ] Wizard: dialog titles, card titles, and the Cancel / Continue /
      Create Wallet buttons.
  [ ] CRITICAL - still monospaced AND still aligned: wallet balance,
      the amount column in the UTXO and transaction lists (digits
      must line up vertically down the column), addresses, xpubs,
      txids, dates, the fingerprint field, the seed word grid, the
      Logs view, text fields and combo boxes.
      A ragged column of numbers means that class needs pinning.
  [ ] Copy buttons (Receive screen, and the wizard fingerprint):
      clicking swaps the copy glyph to a tick and back with NO change
      in size or position. A jump means .copy-icon-btn lost its
      "System" font override and the glyph is falling back.
  [ ] Transaction / UTXO cells: the user's label, PayNym name, mix
      badge and explorer links are in the app face; ONLY the amount
      and the address/txid stay monospaced. Amounts still line up
      down the column.
  [ ] Guided tour (replay from Settings): every coach-mark is in the
      app face, and every bubble looks the SAME as every other one
      whatever control it points at. A bubble with a different size
      or face means #tourPopover stopped terminating inheritance.
  [ ] Tools -> Whirlpool Stats: "TOTAL BTC IN POOLS" matches the
      other headings, with the figure under it still monospaced.
  [ ] No tofu boxes anywhere, including wallet names and the version
      number in the title bar. Watch the mix badge in particular -
      it renders a tick the app face does not have, so that glyph
      falls back inline. If it reads badly, pin .mix-badge-text to
      "System" the way .copy-icon-btn is.
  [ ] JUDGEMENT: nothing given this face carries bold any more, since
      it has a single weight. Check the hierarchy still reads, and
      that proportional chrome next to monospaced data looks
      deliberate. Any class can be reverted on its own.
